# Tandau — реестр изображений и шрифтов

**Версия 3.1 · 23 сентября 2026**

Этот реестр отделяет то, что уже получено и используется, от будущих изображений и локального архива. Он не заменяет дизайнбук: геометрия, компоненты и способы применения описаны в [`TANDAU_DESIGNBOOK.md`](TANDAU_DESIGNBOOK.md).

## 1. Статус пакета

| Группа | Количество | Статус | Использование |
| --- | --- | --- | --- |
| Активные растровые 3D-изображения | 5 в интерфейсе, 6 одобрены в запас | Веб-копии JPEG в `img/` | По одному акценту на секцию лендинга и `/app` |
| Новые предметные изображения Tandau | 16 заданий, 14 файлов получено | 11 приняты, 3 на доработку, 2 не получены | Раздел 4 |
| Собственные функциональные SVG-иконки | 1 спрайт, 22 символа | Готов | Кнопки, поля, навигация, форматы мероприятий, статусы |
| Локальный variable font Geist | 1 WOFF2 + лицензия и provenance | Получен, подключён | Весь интерфейс и дизайнбук |
| Архивная растровая графика | 10 PNG | Архив, не production | Девять PDF-фрагментов и `fluid-card.png`; в продукте не отображаются |

Интерфейс читается и без изображений: форма события, пример, объяснения и состояния остаются текстом. Hero показывает типографическую карточку события. Отсутствующие PNG не заменяются пустыми слотами, ранними 3D-схемами или вымышленными финальными изображениями.

Будущие пути изображений определяются в [`TANDAU_ASSET_BRIEFS.md`](TANDAU_ASSET_BRIEFS.md). Их не нужно создавать как пустые файлы. Когда пользователь передаст изображения, принятые веб-копии попадут в активную папку с однозначными Tandau-именами; оригиналы сохраняются отдельно от оптимизированных копий. Manifest обновляется по факту, а не заранее выдаёт pending-файл за существующий.

Все размещённые изображения декоративные: `alt=""`, явные `width`/`height`, `loading="lazy"` ниже первого экрана. Цена, даты и происхождение данных остаются текстом рядом.

В реестре каждого файла после получения нужны:

| Поле | Требование |
| --- | --- |
| `id` | Совпадает с ID из брифа, не зависит от случайного имени загрузки |
| `status` | pending / received / inspected / approved / integrated / revision_requested |
| `original_file` | Реальное имя полученного оригинала; пусто до получения |
| `web_file` | Реальный путь принятой веб-копии; пусто до подготовки |
| `source` | «Предоставлено пользователем» и известные подробности; неизвестное не придумывать |
| `received_at` | Дата фактического получения |
| `width`, `height`, `format` | Измеряются по файлу |
| `alpha` | Фактический alpha-канал; картинка шахматной сетки не является прозрачностью |
| `sha256` | Контрольная сумма конкретной версии файла |
| `usage` | Разрешённые места применения, без подмены функциональных фактов |
| `crop` | Проверенная позиция кадра для desktop/mobile |
| `alt` | Пустой для декора или локализованное описание для смыслового изображения |
| `review_notes` | Недочёты, ограничения и решение по интеграции |

Не помещать новое изображение в карточку анонимизированного подрядчика как его портрет. Категорийная иллюстрация — иллюстрация услуги, а не фотография конкретного исполнителя или места. Знак «успех» не означает гарантию бронирования. Изображение календаря не заменяет календарные данные CSV.

## 5. Проверка поступивших изображений

1. **Соответствие брифу.** Проверить объект, композицию, направление света, перспективу, свободное поле и назначение. Проверка проводится на оригинале, а не только на уменьшенной миниатюре.
2. **Самостоятельная идентичность.** Нет посторонних логотипов, названий, водяных знаков, случайной типографики и декоративных UI-скриншотов.
3. **Материал и цвет.** Реальные материалы оборудования, бумаги и рабочих предметов. Чёрный `#000000`, нейтральные серые и функциональная синяя деталь `#2B5FE3`.
4. **Фон.** Для отдельного объекта нужна заданная прозрачность. Для широкой сцены нужна цельная поверхность без швов. Края проверяются на белом и чёрном.
5. **Размер и резкость.** Исходник достаточен для целевого отображения; нет растяжения, заметных артефактов и обрезанных важных частей.
6. **Кропы.** Desktop и mobile проверены отдельно. Ключевой объект не исчезает при узком кадре.
7. **Веб-оптимизация.** Сохранить оригинал и подготовить локальную копию. Сжатие сохраняет материалы и границы предмета. Явные размеры предотвращают сдвиг страницы.
8. **Смысл и доступность.** Интерфейс читается без изображения. Декор исключён из дерева доступности через пустой alt. Никаких доказательств, существующих только в картинке.
9. **Реестр.** Обновить статус и manifest только после успешной проверки. Записать точное место интеграции.

Если пункт не выполнен, записать конкретную правку и оставить `revision_requested`. Не отмечать ассет integrated только потому, что его файл можно открыть.

Проверенные тестовые алфавиты: русский, английский и казахские буквы `ӘҒҚҢӨҰҮҺІәғқңөұүһі`. В соответствующей карте TTF 728 codepoints. Light 300 может использоваться для крупных чисел; длинные объяснения и обязательные подписи не набираются сверхтонким весом. Шрифт загружается локально; внешняя сеть для отображения не нужна.

## 9. Приёмка всего пакета

- [ ] В активных шаблонах и CSS нет PNG из архива, включая волну.
- [ ] Геометрия экрана соответствует токенам: поверхности 0, контролы 4, метки 2, overlays 8 px.
- [ ] Новые изображения имеют индивидуальный статус; ни один pending не заявлен готовым.
- [ ] 16 функциональных SVG-символов доступны локально; 16 предметных изображений честно помечены pending.
- [ ] Брифы и реальные имена файлов согласованы; битых ссылок нет.
- [ ] Нет ссылок на архивные изображения в активных экранах.
- [ ] Каждый принятый файл имеет размеры, alpha-статус и контрольную сумму.
- [ ] У изображений корректный alt и явные размеры; mobile-кроп проверен.
- [ ] Локальный Geist загружается, казахские буквы видимы, `₸` отображается fallback-шрифтом.
- [ ] Информация о цене, происхождении и доступности остаётся настоящим текстом рядом с карточкой.
- [ ] README описывает фактически полученные и подключённые материалы, а не весь запланированный набор.
