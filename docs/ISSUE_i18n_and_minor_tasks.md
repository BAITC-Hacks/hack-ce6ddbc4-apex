## Общие правила приёмки

1. В каждом issue указать проверенный commit SHA, что изменено и что осталось заблокировано.
2. Не менять исходный CSV, идентификаторы подрядчиков, условия фильтрации, API и названия русских значений данных. Код казахского языка — `kk`, не `kz`.
3. Не скрывать бейджи синтетики и ориентировочных данных, не выдумывать отзывы, рейтинги, успешные бронирования, интеграции и подтверждённую доступность.
4. Новые русские ключи добавляет главный разработчик; @yassmn126 переводит их в KZ/EN. Не удалять ключ, если он пока используется только планируемым экраном.
5. Не перезаписывать файлы, которые одновременно меняет другой участник. Сначала сверить владельца файла и текущую версию; перед передачей проверить diff.
6. Для изменений словарей запустить существующие `tests/test_i18n.py` и `tests/test_pages.py`; перед передачей основной ветке — весь существующий набор. Для одних документов/картинок новые unit-тесты не нужны.
7. Не коммитить `.env`, `var/`, виртуальное окружение или секреты. Скриншоты содержат только интерфейс проекта.
8. Ошибка вне своей области — короткая запись с шагами воспроизведения и передача главному разработчику, без расширения задачи на полноценную разработку.
