# [Design] Внедрить дизайн-систему Tandau в семь фаз продукта

**Владелец:** главный разработчик проекта; GitHub assignee не задан.  
**Приоритет:** P1 — основная задача, вспомогательные работы вынесены отдельно.  
**Формат:** семь последовательных этапов с отдельной проверкой готовности. Календарный срок в этом issue не назначается.

## Результат и исходное состояние

Перенести утверждённую систему Embico → Tandau из отдельного дизайнбука в рабочие экраны продукта: лендинг, регистрация, вход, подбор, объяснения, кабинет и итоговая проверка. Сохранить простой локальный запуск, гостевой доступ к подбору и фактическую честность карточек.

**Уже сделано:** создан самостоятельный маршрут `/designbook`, `app/templates/designbook.html`, локальные `app/static/css/designbook.css` и `app/static/js/designbook.js`; подробная спецификация — `docs/TANDAU_DESIGNBOOK.md`. Страница содержит библиотеку компонентов и переключаемые образцы семи фаз. Локальные ассеты и Geist уже подключены к дизайнбуку.

**Ещё не означает готовность продукта:** auth, подбор и кабинет. `/app`, `/login`, `/register` на исходном этапе остаются заглушками. Формы и результаты внутри `/designbook` — подписанные образцы поведения, а не работающие endpoints. Нельзя закрыть этот issue только по наличию красивых демонстраций.

## Источники и документы

- `docs/TANDAU_DESIGNBOOK.md` — визуальные токены, кнопки, поля, контейнеры, состояния, семь экранов и правила адаптации.
- `docs/00_MASTER_PLAN.md` — стек, маршруты, backend-контракты, локализация и роли.
- `docs/01_REFERENCE.md` — требования кейса, данные, демо-сценарии и глоссарий.
- `docs/PHASE_1_FOUNDATION_AND_LANDING.md` — исходный фундамент; его старый запрет на иллюстрации заменён текущим запросом на Embico-дизайн.
- `docs/EMBICO_ASSET_INVENTORY.md`, `app/static/assets/embico/manifest.json` — происхождение девяти извлечённых PNG, ограничения и запросы оригиналов.
- [Live Figma Embico](https://www.figma.com/design/Qw7e2YZbnTtyiH1b25A820/embico?node-id=42-2): проверены Design Book v2 — цвета `44:2`, типографика `44:59`, кнопки `45:2`, обложка `58:2`.

## Общие контракты интеграции

1. Сохранить Python/FastAPI/Jinja2 и локальные CSS/JS. Не добавлять обязательную фронтенд-сборку или CDN ради переноса компонентов.
2. Не подключать `designbook.css` целиком к старому `base.html`: в отдельном документе есть глобальный reset. Сначала выделить общие семантические токены/компоненты и проверить их область действия. Компоненты дизайнбука имеют префикс `db-`; переход выполнить явно, не смешивая две системы случайно.
3. Общие компоненты: кнопки primary/secondary/ghost/text/icon и размеры; поля и подсказки; error summary; контейнеры/сетки; навигация; карточки/бейджи; пять status banner; пустое, loading, error и success; раскрытия; календарь; списки истории/избранного. На каждом рабочем экране есть состояния default, hover, focus, disabled и pending там, где применимо.
4. Подбор, сравнение и профиль остаются публичными; вход добавляет историю и избранное. Демо-пресет заполняет видимые поля, а не выдаёт подготовленный ответ за новый запрос.
5. Сохранять пять статусов `found`, `partial`, `no_category_in_city`, `none_match`, `invalid_request`, до трёх карточек и детерминированный порядок. Интерфейс не меняет условия фильтрации и исходный CSV.
6. Внутренние значения справочников/API остаются русскими. Тексты продукта проходят через существующий `t()`/`label()`, языки — `ru`, `kk`, `en`. Новые ключи сначала в RU, затем передаются на перевод.
7. Цена всегда «от»; синтетические/проставленные при подготовке поля помечены. Отсутствие занятой даты в CSV не выдаётся за подтверждённое бронирование. Показатели score не являются вероятностью успеха.

## Фаза 1 — фундамент и лендинг

- [ ] Вынести повторно используемые токены и компонентные правила из дизайнбука с сохранением работающей отдельной библиотеки.
- [ ] Перенести бренд в `base.html`, header/footer и `landing.html`: Geist, палитра, контейнеры, кнопки, типографика, сетки и умеренная 3D-графика.
- [ ] Сохранить hero → гостевой CTA → подписанный пример → шаги → объяснение пустых исходов → живые цифры → FAQ → footer.
- [ ] Статистика по CSV, переключение языка, мобильное меню и ссылки работают; `/designbook` и API `/docs` не перепутаны.

**Приёмка:** 390/1440 px, все три языка, клавиатура; пример обозначен как пример, декоративные файлы не закрывают текст и не ломают страницу при ошибке загрузки.

## Фаза 2 — регистрация

- [ ] Реализовать GET/POST `/register` по backend-контракту; только затем заменить заглушку настоящей формой.
- [ ] Собрать форму из общих полей/кнопок: имя, email, пароль, показать пароль, правила, вход и «Продолжить без входа».
- [ ] Отобразить invalid email, правила пароля, занятый email, pending, CSRF/устаревшую форму, техническую ошибку и реальный успех. Сохранить имя/email при обычной ошибке.

**Приёмка:** аккаунт реально создан, пароль хранится по контракту, авто-вход работает, повторная отправка не создаёт дубликат; доступность полей, password manager и вставка работают. Макет регистрации не считается выполнением.

## Фаза 3 — вход, сессии и доступ

- [ ] Реализовать GET/POST `/login`, POST `/logout`, проверку сессий и защиту личных маршрутов.
- [ ] Применить одинаковые auth-контейнеры и состояния: неверные данные, pending, ошибка, истекшая сессия, успех.
- [ ] Добавить demo-вход только вместе с реально работающим seed/flow; безопасный внутренний `next`, меню аккаунта после входа, возвращение к исходному запросу.

**Приёмка:** logout не GET-ссылка; неверный вход не раскрывает существование email; личные маршруты защищены, гостевой подбор открыт. Нет пустого «Забыли пароль?» без реализации.

## Фаза 4 — форма подбора и результаты

- [ ] Подключить `/app` и `/api/recommend` к реальному движку; справочники брать из `/api/meta`.
- [ ] Форма: город, дата, формат, категория, бюджет; дополнительные длительность, язык и пожелания. Desktop — форма рядом с результатом, mobile — последовательно.
- [ ] Реализовать initial, pending, error, изменённые условия и пять исходов; summary запроса, до трёх карточек, цена/флаги и сообщение «ещё N» только по ответу API.
- [ ] После запроса объявлять результат доступно, без искусственного ожидания; запрос можно повторить ссылкой.

**Приёмка:** подбор работает без входа; повтор даёт тот же порядок; занятый кандидат не попадает в результаты; пустота объяснена текстом. Переключение образцов дизайнбука не используется вместо движка.

## Фаза 5 — объяснения и сравнение дат

- [ ] Перенести раскрытия «Почему подходит», «Почему не больше», причины отсева, честные подсказки и воронку из фактов движка.
- [ ] Реализовать `/app/compare`: одинаковые условия, две даты, две читаемые группы результатов и изменения с конкретной причиной.
- [ ] Не складывать пересекающиеся причины отказа как число уникальных исключённых. Исходные цитаты сохранять с отметкой «по описанию».
- [ ] При наличии внешнего редактора текста сохранить полностью работающий шаблонный fallback без ключей.

**Приёмка:** S2 различает 10 и 17 октября по занятости; объяснения двух карточек различимы без имён; смысл понятен без цвета/наведения; неизвестные факты не добавлены.

## Фаза 6 — кабинет, история, избранное и профиль

- [ ] Реализовать `/account/history`, `/account/shortlist`, `/contractors/{id}` и связанные действия по контракту; повторно использовать карточки/списки/пустые состояния.
- [ ] Повтор истории пересчитывает запрос; избранное связано с текущим пользователем; удаление сохраняет понятный фокус/обратную связь.
- [ ] Профиль показывает данные и календарь 23.09–31.12.2026 с легендой «Занят / Не отмечен занятым / Нет данных».

**Приёмка:** пустой кабинет имеет полезный CTA; профиль публичен; личные списки защищены; нет вымышленных контактов, фотографий, отзывов, бронирований и неподдерживаемых кнопок.

- [ ] Пройти S1–S7 из справочника по мере реализации; фиксировать фактические результаты, а не только ожидаемые.
- [ ] Обновить README: реализованное, планы, ограничения, данные, запуск, демо-доступ после его реализации; зафиксировать SHA и версии ассетов.

**Приёмка:** основной путь проверяется без личного аккаунта разработчика; каждый из семи этапов либо принят действием, либо явно остался открытым. Дизайнбук не используется как доказательство работающей регистрации или подбора.

## Ассеты и шрифт

Девять PNG в `app/static/assets/embico/` — извлечения из предоставленного PDF с сохранённым фоном и исходным разрешением. Существующие квадратные изображения 240 × 240 использовать примерно на 88–120 CSS px. `chain-3d.png`/`stack-3d.png` требуют поверхности `#FAFAFB`; четыре других квадратных — белой. Оригинальные прозрачные PNG/SVG можно подключать после сверки в отдельной задаче, с сохранением происхождения.

Шрифт `app/static/fonts/Geist-Variable.woff2` взят из официального `geist@1.7.2`; рядом `Geist-OFL.txt`, `README.md`, `geist-provenance.json`. Сохранить лицензию и `font-display: swap`. Проверка соответствующего TTF показала наличие тестовых букв RU/KK/EN; символ `₸` отсутствует — системный fallback обязателен. Не выдавать этот шрифт за извлечённый из PDF.
