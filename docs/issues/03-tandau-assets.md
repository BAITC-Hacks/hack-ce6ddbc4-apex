# [Assets] Проверить и подготовить к подключению 16 новых ассетов Tandau

**Исполнитель:** @yassmn126
**Приоритет:** средний; подготовку реестра начать сейчас, проверку файлов — по получении
**Оценка:** 40–60 минут активной работы; генерация и ожидание файлов отдельно
**Зависимости:** пользователь создаёт 16 новых изображений по `docs/TANDAU_ASSET_BRIEFS.md`; основной разработчик утверждает композицию и место каждого изображения.

## Цель и текущее состояние

Принять, проверить и организовать **16 новых ассетов Tandau**, которые предоставит пользователь. Все 16 сейчас ожидаются. Основной брендинг, композиция экранов, CSS и шаблоны принадлежат главному разработчику.

Волна перемещена в `app/static/assets/tandau/archive/fluid-card.png`. Она входит в **10 архивных PNG** и больше не используется в актуальном интерфейсе. Старые изображения не являются образцом для новой коллекции.

В `app/static/assets/tandau/tandau-icons.svg` остаются **16 плоских функциональных SVG-иконок**. Они обслуживают кнопки и навигацию и не входят в 16 ожидаемых предметных изображений. Бриф или слот на странице не считается готовым изображением.

## Файлы и границы владения

- Читать: `docs/TANDAU_ASSET_BRIEFS.md`, `docs/TANDAU_DESIGNBOOK.md`.
- Дополнять: `docs/TANDAU_ASSET_INVENTORY.md`, `app/static/assets/tandau/manifest.json`.
- Добавлять полученные оригиналы и согласованные веб-версии только в `app/static/assets/tandau/` по именам из брифов.
- Вести результаты проверки в `docs/qa/ASSET_QA.md` (создать при первом получении).
- Не менять `app/static/css/`, `app/static/js/`, `app/templates/`, маршруты и backend. Передать готовые файлы основному разработчику; после подключения проверить их в браузере.

## Что сделать

1. Скопировать в реестр 16 слотов из `TANDAU_ASSET_BRIEFS.md` с точным ID/именем, назначением, ожидаемым форматом/размером и статусом `awaiting`. Сначала проверить три калибровочных изображения по брифу, затем остальные. Не создавать параллельный набор.
2. При получении файла записать фактическое имя, связь со слотом, дату/источник передачи, формат, размеры, вес, прозрачность, checksum и статус `received`. Пользовательская генерация — фактический источник; не выдавать новый файл за старый векторный оригинал.
3. Сверить изображение с брифом. Основной материал имеет нейтральный чёрный цвет `#000000`, без тёмно-синего подтона. Палитра состоит из чёрного, белого, серого, хрома и небольших кобальтовых деталей. Проверить композицию, свободное пространство, пропорции, фон и отсутствие посторонних надписей. Волны и синее стекло в новую коллекцию не входят.
4. Проверить целостность и разрешение. Сохранить исходный файл; производные веб-версии делать только с понятным именем, без незаметного перезаписывания исходника. Не удалять фон и не дорисовывать изображение самостоятельно; несоответствие вернуть списком замечаний владельцу генерации.
5. Для прозрачного PNG/WebP проверить реальные альфа-данные, а не нарисованную «шахматку». Для непрозрачного файла записать цвет фона, чтобы основной разработчик выбрал подходящую поверхность.
6. Передать каждую готовую пару «слот → файл» с ожидаемым экраном и рекомендуемым размером. У готовности два отдельных статуса: `ready` — файл проверен, `integrated` — он реально подключён основным разработчиком и проверен в браузере.
7. После подключения проверить `/designbook` и полный образец `/designbook/landing` на 375 px и 1440 px. Проверить 404, пропорции, обрезание, наложение на текст и скачки макета. Проверить `width`/`height`, подходящий `alt` и локальную загрузку без CDN. Функциональные SVG-иконки должны оставаться чёткими и различимыми в навигации, верхней панели запроса и карточках.
8. Сверить геометрию окружающих компонентов с Tandau: панели/карточки **0 px**, кнопки/поля **4 px**, бейджи **2 px**, диалоги **8 px**. Органическая форма самого изображения не меняет радиус контейнера. Проблемы CSS передать главному разработчику.
9. Остаток оформить конкретно: ID слота → что не получено/не подходит → требуемое исправление. Один и тот же готовый ресурс повторно не запрашивать.

## Критерии приёмки

- [ ] Ровно 16 новых слотов из брифов учтены со своими статусами; ни один неподанный файл не отмечен готовым.
- [ ] Все 10 архивных PNG, включая `archive/fluid-card.png`, отсутствуют в актуальных экранах.
- [ ] 16 плоских функциональных SVG-иконок сохранены отдельно от новых предметных изображений.
- [ ] Чёрные материалы нейтральны и соответствуют брифу `#000000`; волны и синее стекло не возвращены.
- [ ] Все полученные файлы имеют понятное происхождение, размеры, формат, checksum и назначение.
- [ ] Локальные пути, имена и manifest согласованы; новых внешних зависимостей нет.
- [ ] Каждый статус `integrated` подтверждён URL, SHA и реальной проверкой в браузере.
- [ ] Геометрия 0/4/2/8 соблюдена; неисправности переданы владельцу CSS.
- [ ] В актуальном UI, документах задачи, названиях и подписях ресурсов используется только бренд **Tandau**.
- [ ] Если часть изображений ожидается, issue остаётся открытым с точным списком оставшегося; выдавать 16/16 за выполненное заранее нельзя.

**Передача:** обновлённый manifest/inventory, полученные файлы, короткий QA-отчёт и перечень ожидаемых слотов. Пример коммита после проверки: `chore: prepare Tandau generated assets for integration`.
