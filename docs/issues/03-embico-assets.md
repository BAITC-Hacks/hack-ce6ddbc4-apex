# [Assets] Сверить Embico с live Figma и дополнить оригинальные экспорты

**Исполнитель:** @yassmn126  
**Приоритет:** средний; сверку начать сейчас, импорт — при получении оригиналов  
**Оценка:** 20–30 минут активной работы, ожидание файлов отдельно  
**Зависимости:** текущие извлечённые ассеты уже доступны; для замены на прозрачные оригиналы нужны экспорты из Figma или файлы от владельца проекта.

## Источник и текущий статус

Референс пользователя: [Embico, Figma node 42:2](https://www.figma.com/design/Qw7e2YZbnTtyiH1b25A820/embico?node-id=42-2). Пользователь готов предоставить нужные ассеты по запросу.

Уже выполнено: локальный 29-страничный PDF осмотрен, из него извлечены **9 PNG**; файлы и `manifest.json` лежат в `app/static/assets/embico/`. Источники, размеры, координаты, ограничения и контрольные суммы описаны в `docs/EMBICO_ASSET_INVENTORY.md`. Это прямоугольные растровые фрагменты с исходным фоном, а не прозрачные оригиналы Figma. Повторять извлечение не нужно.

**Обновление 23 сентября:** пользователь выбрал насыщенный синий фон с волной из своего скриншота. Совпадающий локальный оригинал `fluid-card.png` добавлен десятым ассетом (1536 × 1024, RGB PNG, 1 869 098 байт), без изменения исходных байтов. Он заменяет бледную волну в hero, образцах авторизации и экранов дизайнбука. Источник — предоставленный локальный файл из Downloads, визуально сверенный со скриншотом; это не новый экспорт из live Figma. **`fluid-card` уже получен — не запрашивать повторно.** Девять PDF-фрагментов сохранены в архиве/галерее.

Главный разработчик также осмотрел в live Figma раздел **Design Book v2**: цвета `44:2`, типографику `44:59`, кнопки `45:2`, обложку `58:2`. Эти наблюдения и PDF относятся к разным представлениям источника; нужно согласовать их и добрать оригинальные PNG/SVG, не объявляя PDF полным экспортом Figma.

## Файлы

Единый корень **`app/static/assets/embico/`**. Уже существуют `manifest.json`, `fluid-card.png`, `documents-3d.png`, `chain-3d.png`, `restricted-cube-3d.png`, `timer-3d.png`, `stack-3d.png`, `grid-3d.png`, `glass-wave-wide.png`, `glass-wave-blue-edge.png`, `cobalt-grid-strip.png`.

- Дополнять существующий `manifest.json` и `docs/EMBICO_ASSET_INVENTORY.md`; второй независимый реестр не создавать.
- Для новых оригинальных экспортов при необходимости создать `originals/`, для UI SVG — `icons/`. Существующие пути изображений не переименовывать: они используются дизайнбуком.
- Шрифты добавлять только если есть реальные файлы, разрешение на использование и выбор главного разработчика. Не угадывать семейство по PDF.
- Отсутствующие PNG/SVG нельзя заменять пустыми файлами. Не перезаписывать растровый фрагмент новым оригиналом до согласования источника и проверки в интерфейсе.

## Что сделать

1. Прочитать существующие inventory и manifest. Проверить, что все 10 файлов открываются и соответствуют указанным ограничениям. Сохранить разницу между девятью PDF-фрагментами и локальным оригиналом `fluid-card.png`; не выдавать текущие квадратные фрагменты 240 × 240 за прозрачные @2x-экспорты.
2. Сверить live Figma Design Book v2 с PDF и текущим дизайнбуком: цвета, семейство/начертания, кнопки, радиусы, SVG-иконки и 3D-объекты. Зафиксировать «наблюдено в Figma», «извлечено из PDF», «адаптировано для Tandau» отдельно. По каждому расхождению дать конкретный слой/node и значение либо пометить неизвестное.
3. Дополнить инвентарь оригинальных экспортов, включая неиспользуемые: имя слоя; node ID/ссылка; путь; формат; размеры; вес; прозрачность; назначение; состояние received / ready / missing / not-used; источник/разрешение, если предоставлено. Оставшиеся приоритеты: шесть 3D-оригиналов на прозрачном фоне, отдельные стеклянные иконки, `cover-hero`, `fluid-auth` и UI SVG из кнопок. Сначала проверить локальные кандидаты `cover-hero` и `fluid-auth`, ещё не импортированные в пакет; запрашивать только недостающие варианты. `fluid-card` уже готов и не требует нового экспорта.
4. Имена новых файлов: строчные латинские слова через дефис, по реальному содержимому. Не менять идентичность или цвет экспортов без решения по брендингу. Сохранить визуально точные оригиналы; для SVG проверить viewBox и отсутствие внешних ссылок/скриптов.
5. Проверить фон и разрешение: `chain-3d.png` и `stack-3d.png` имеют фон `#FAFAFB`, остальные квадратные — белый. Текущие фрагменты рекомендуются для 88–120 CSS px. У новых прозрачных оригиналов отметить, какие ограничения сняты; не применять искусственное удаление фона к старым файлам.
6. Привязать каждый новый файл к месту: hero, «как работает», пустое состояние, карточка образца, библиотека дизайнбука. Не расставлять все 3D-объекты по рабочим формам ради количества.
7. Для оставшихся ресурсов составить точный запрос: конкретный слой/node, SVG, PNG/WebP @2x с прозрачным фоном, подтверждённое семейство/начертание шрифта. Уже полученные PDF, Geist и `fluid-card.png` повторно не запрашивать.
8. Передать главному разработчику обновлённый реестр, таблицу расхождений и список готовых замен. Интеграцию и переключение путей в CSS/шаблонах выполняет он.

## Критерии приёмки

- [ ] Существующие 9 файлов и их происхождение сохранены, повторное извлечение не выполнено.
- [x] Выбранный `fluid-card.png` учтён как локальный оригинал; он исключён из списка запросов, девять PDF-фрагментов не перезаписаны.
- [ ] PDF и live Figma сверены с указанием конкретных осмотренных фреймов; различия источников отражены честно.
- [ ] Каждый новый оригинал учтён в существующем manifest/inventory; нет потерянных, неименованных или дублирующихся копий.
- [ ] Локальные пути начинаются с `app/static/assets/embico/`; внешние CDN-ссылки не нужны для отображения.
- [ ] Формат, размеры, прозрачность и вес проверены; файлы открываются.
- [ ] Web-версии сохраняют узнаваемость и пропорции исходных элементов.
- [ ] Неизвестные node ID/лицензия/шрифт обозначены как неизвестные, а не выдуманы.
- [ ] Отсутствующие файлы перечислены отдельным списком с точным требуемым экспортом.
- [ ] Если нужные оригинальные экспорты ещё не получены, остаток issue явно ожидает ассеты; существующий дизайнбук с PDF-фрагментами остаётся рабочим.

## Границы

Не создавать новую визуальную концепцию вместо референса, не генерировать похожие 3D-объекты как «оригинал», не рисовать новый логотип, не менять CSS-токены, тексты, backend и текущие изображения без координации. Публикация/покупка ассетов и шрифтов не входит.

**Передача:** локальный реестр, список готовых файлов, список недостающего и сведения о том, какие ресурсы реально осмотрены. Пример коммита: `chore: organize supplied Embico design assets`.
